# Testing Standards

## Overview

job-collector currently emphasizes a Bun e2e script over a full unit-test suite. Prefer adding focused unit tests for parsers/pipeline as features grow; keep e2e for smoke coverage of the API and critical flows.

## Testing Framework

**Framework**: Bun test (preferred for new unit tests) + custom e2e script
**Runner**: `bun` / `bun scripts/e2e-test.mjs`

## Test Types

| Type | Tool | Location | When to Use |
|------|------|----------|-------------|
| Unit | Bun test | `tools/job-collector/**/*.test.js` (colocate or `__tests__/`) | Parsers, DB helpers, error mapping, pure pipeline transforms |
| E2E / smoke | `scripts/e2e-test.mjs` | `tools/job-collector/scripts/` | API health, core job CRUD / collect path |
| Manual | Browser + Vite UI | — | Scraper auth flows, CV preview UX |

## Coverage Requirements

**Target**: 60% for new critical modules (pipeline parse, error helpers); no global gate yet
**Enforcement**: Soft — raise when adding Jest/Bun coverage to CI

**Critical paths that MUST have coverage:**
- Job parse / JSON extraction from LLM output (`pipeline/parser.js`)
- HTTP error mapping (`server/errors.js`)
- CV generation grounding (no invented facts from master profile)
- Deduplication / duplicate URL handling

## Test Naming

**Pattern**: `{module}.test.js` or describe/it sentences describing behavior

**Examples**:
- `parser.test.js` — extracts structured job fields from LLM JSON
- `errors.test.js` — maps `OLLAMA_UNAVAILABLE` to 503
- `e2e-test.mjs` — health check and happy-path API smoke

## Test Structure

```javascript
import { describe, expect, test } from 'bun:test';
import { statusForError } from '../server/errors.js';

describe('statusForError', () => {
  test('maps OLLAMA_UNAVAILABLE to 503', () => {
    expect(statusForError({ code: 'OLLAMA_UNAVAILABLE' })).toBe(503);
  });
});
```

## Mock Strategy

**Approach**: Mock external I/O (LLM, Playwright, network); use real SQLite in temp dirs for integration when needed

**Guidelines**:
- Do not hit live LinkedIn/Indeed in automated tests
- Stub Ollama/Anthropic responses with fixtures
- Prefer fixture HTML/markdown over live scrapes

## Test Data

**Strategy**: Fixtures under `tools/job-collector` (or `scripts/fixtures/`) — anonymized offer text

**Guidelines**:
- No real personal contact data in fixtures
- Keep master-profile samples minimal and fictional for tests
- Reset SQLite test DB between runs

## Running Tests

```bash
# Run all tests (when unit tests exist)
cd tools/job-collector && bun test

# Run with coverage (Bun)
cd tools/job-collector && bun test --coverage

# Run specific test file
cd tools/job-collector && bun test server/errors.test.js

# Run e2e smoke
cd tools/job-collector && bun run test:e2e

# Run in watch mode
cd tools/job-collector && bun test --watch
```
