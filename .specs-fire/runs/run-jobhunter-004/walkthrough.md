# Implementation Walkthrough: Profile document access and API

## Summary

Added server-side read and manual-save endpoints for the master profile Markdown file. All access is pinned to the configured `PROFILE_PATH` under `REPO_ROOT`; saves validate via `parseProfileText()` before writing and invalidate the parsed-profile SQLite cache on success.

## Structure Overview

The Express route (`/api/profile`) delegates to pipeline helpers in `profile.js`, which reuse `readRepoFile` / `writeRepoFile` from `repoFiles.js`. Validation errors propagate through the global error handler using machine-readable `code` fields. Frontend API methods are stubbed for the upcoming Profile editor page.

## Key Implementation Details

### 1. Validate-before-write

`saveProfileMarkdown` calls `parseProfileText` before `writeRepoFile`. Any throw leaves the on-disk file untouched.

### 2. Cache invalidation

`invalidateProfileCache` nulls `parsed_profile` and `parsed_profile_mtime` settings so CV/apply flows re-parse after edits.

## Security Considerations

| Concern | Approach |
|---------|----------|
| Path traversal | No client path; only `PROFILE_PATH` env default |
| Data leakage in logs | Routes do not log profile body |
| Invalid data on disk | Validation gate before write |

## Decisions Made

| Decision | Choice | Rationale |
|----------|--------|-----------|
| HTTP verb for save | `PUT /api/profile` | Idempotent full-document replace |
| Error code for incomplete profile | 422 `PROFILE_INCOMPLETE` | Aligns with parse/validation semantics |
| Self-check scope | Pipeline helpers only | Faster, isolated temp dir; matches work item |
