## Key Implementation Details

### 1. Apply URL on job record

`apply_url` is a nullable TEXT column added via the same `addColumnIfMissing` pattern as `applied_at`. PATCH accepts `applyUrl` with http/https validation. Job Detail exposes edit + open link.

### 2. Company-site agent prompt

`docs/agents/apply-form.md` now targets careers/ATS forms with host hints (Greenhouse, Lever, Workday, Personio, etc.), label-based filling, and the same safety contract (`SUBMIT = false`, EEO skip, no fetch).

### 3. Route and UI pivot

`POST /api/apply/script` requires `applyUrl` (409 `APPLY_URL_MISSING`). Generate button gated on CV + apply URL. "Record application" stores `appliedUrl` from `applyUrl` (fallback `sourceUrl`).

## Decisions Made

| Decision | Choice | Rationale |

| URL field separation | `apply_url` vs `source_url` | Listing stays LinkedIn; company form is user-provided |
| Missing apply URL | Hard 409 in route (item 3) | Soft warning in item 2 was interim until UI field existed |
| LLM self-check failures | Warn-skip on timeout/bad output | Provider flakiness shouldn't fail CI-style checks |
| markApplied URL | `applyUrl` preferred over `sourceUrl` | Records where application was actually submitted |
